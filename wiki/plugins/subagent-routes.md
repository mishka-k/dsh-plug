# subagent-routes — выбор маршрута для субагентов

## 1 Зачем

В стоковом DSH агент не может выбрать провайдера, модель и усилие для субагента. Причины три, и они
разные по природе:

| Что | Где заперто | Можно ли починить плагином |
|---|---|---|
| выбор выключен | `tool-subagent.modelSelectionSettings: false`, список маршрутов живёт в секции `subagent-model-selection-settings` | да, настройкой |
| политика только «свежей» сессии | `freshSession = target.firstLiveSeq === 0` в `@deepseek-ai/dsh-tool-subagent` | да, дописав событие сессии |
| усилия нет в политике | событие несёт только `{provider, model}`; усилие — `agentOptions.reasoningEffort` строки инструмента | нет, это другая настройка |

Плагин закрывает второй пункт и показывает третий честно, вместо того чтобы делать вид, что он про
маршруты.

## 2 Как устроено

| Половина | Что делает |
|---|---|
| Host (`index.js`) | на `session/created` дописывает `subagent/model-selection-policy`, если секция включена, политики ещё нет и сессия не ребёнок |
| Client (`client.js`) | вкладка Settings → Plugins: провайдеры группами, переключатель на провайдера целиком, счётчик, одна кнопка сохранения; усилие показывается только для чтения |

Данные берутся только из штатных поверхностей: `remote.settings.describe/update` для
неймспейса `subagent-model-selection-settings` и `remote.session.modelCatalog` для живого каталога
адаптеров. Маршрут, который больше не предлагает ни один адаптер, остаётся в списке с пометкой —
иначе сохранение молча выбросило бы его.

Порядок важен: событие пишется на `session/created`, то есть до `agents.announce` и сборки
инструментов, поэтому агент видит политику с первого же хода.

## 3a Инцидент 29.10: падение хоста

Первая версия страницы умела ещё и записывать усилие по умолчанию — через `ctx.loader.update` по
строке `tool-subagent`. Строка принадлежит бандлу, загрузчик её так не адресует и отклоняет промис
(`cannot resolve entry tool-subagent`), а отклонение внутри обработчика маршрута не поймано —
процесс хоста упал, приложение показало «could not start or stopped unexpectedly», пользователю
пришлось жать «выключить сторонние плагины и перезапустить».

Выводы, которые остались в коде и в доках:

- `configEditor` правит только строки профиля (`entries()`), строки бандла в него не входят, хотя
  `configuration()` их показывает;
- любой вызов загрузчика из обработчика маршрута требует `.catch`: отказ приходит асинхронно;
- запись усилия убрана совсем, страница честно говорит, что менять его надо в патче профиля
  (`agentOptions.reasoningEffort` строки `tool-subagent`).

## 4 Подводные камни

- Политика пишется один раз на сессию: правка списка задним числом не переписывает уже открытые
  чаты — это правило харнесса, а не ограничение плагина.
- Дети политику не получают: они наследуют родительскую, и лишнее событие только шумит в логе.
- Усилие рассуждений живёт в `agentOptions.reasoningEffort` строки `tool-subagent`; страница
  маршрутов его не трогает, чтобы не создавать иллюзию, что оно привязано к маршруту.
- Секция `subagent-model-selection-settings` может быть выключена в самом патче профиля — тогда
  страница покажет состояние, но включение сработает только вместе с правкой патча.
